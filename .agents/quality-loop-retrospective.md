# Quality-loop retrospective

Reflection is periodic and advisory. Run it after repeated false passes/bounces or when explicitly
requested; it never gates a Grow or Sharpen result.

## Lessons retained from the retired reflection ledger

- Coverage and mutation counts locate work; they do not prove a scenario or oracle is adequate.
- Grow scenario evidence accepts a focused old-survives/new-kills mutant or a real coverage delta;
  requiring both creates false bounces on covered branches.
- Temporary mutations restore captured bytes without depending on a writable Git index.
- The root executor, not an author agent, classifies pristine behavior and runs deterministic gates.
- Real external I/O is actionable test-tier evidence; bounded sleep polling is advisory.
- Synchronization is observable only when it uses test-owned state or a contractual production effect.
- A preservation witness must be on the target test's executed path and kill the old test before the
  edited test is evaluated.

## Output

A retrospective produces at most three concrete proposals, each supported by repeated run evidence.
Accepted work enters the ordinary contribution path. Clean runs and one-off operational failures produce
no durable record.
